# 玻璃肌肤 · 视觉评估与下一轮优化方案

日期：2026-10-18  
状态：设计提案，未实施、未获视觉定稿确认。  
范围：评价当前主题并确定下一轮方向；不修改主题代码、用户设置或桌面程序。

## 一、结论与设计优先级

**保留玻璃肌肤，不推倒重来；下一轮从“效果迭代”转向“整套界面的美术统筹”。**

主题首先应当让人觉得好看、愿意打开、愿意停留。实用性应在这套美感内部解决，不是把壁纸、冷暖光和材质全部削弱，最后只剩一个不妨碍工作的普通工具界面。

这也不意味着允许文字难读或操作难找：**美观是主导目标，可读与可操作是交付底线，两者不是相互抵扣的分数。** 默认氛围模式必须同时过关，不能要求用户先切到专注模式才正常工作。

建议方向：**冰蓝玻璃围合的深夜创作室，留一束暖光。**

- 壁纸负责场景与情绪，不是可有可无的装饰。
- 冷色中性面板负责秩序，不让整个界面变成高饱和蓝色。
- 暖光负责记忆点，不把所有按钮都染成琥珀色。
- 正文、输入框和当前任务负责视觉落点，不与背景人物争同一个中心。

## 三、当前主题的评价

### 1. 值得保留的部分

**有记忆点。** 冰蓝、暖灯、插画场景比普通深色主题更有个人气质；应在原有方向上精修，而不是改成通用极简灰。

**已经进入小型设计系统阶段。** 排版、材质、状态和配色均有规则，不能再把当前版本描述成“仅仅换色和加背景”。

**中文创作场景选对了。** 阅读排版与界面文字分开处理，有利于形成“安静创作室”而不是“后台管理台”的气质。

### 2. 下一轮最需要解决的事

| 判断 | 依据与限制 | 设计意义 |
|---|---|---|
| 视觉重心需要整屏复核 | 留存截图中人物面部与正文重叠，背景纹理穿过过程文字；不能断言最新版仍同样严重 | 不应只问壁纸够不够清楚，而要看背景、正文、输入框是否各有位置 |
| 材质控制存在全局耦合 | [玻璃开关通过全局基础背景令牌改变画布透明度](<../client.js#L267-L282>) | 不能为了输入框更透，让整屏阅读底色也被动变化 |
| “同一材质”不宜变成“同一强度” | 当前侧栏和输入框都启用玻璃，但承担不同职责 | 侧栏应像磨砂隔断，输入框像精致操作物；同源、不同表现 |
| 规则与现状已经漂移 | [视觉规则仍写玻璃默认关闭、只用于输入框](<../DESIGN.md#L61-L70>)，而[实现和设置文案已默认开启](<../client.js#L317-L323>)并覆盖侧栏 | 后续应统一设计依据，避免按旧说明评价新版本 |
| 语义色仍有可区分性风险 | [深色警告色](<../client.js#L79-L82>)与[装饰琥珀](<../client.js#L127-L129>)同为 `#f0c37e` | 不应只靠色相区分环境光与警告；需要图标、文字和容器共同表达 |
| 视觉验收落后于工程迭代 | [原有验收清单](<../DESIGN.md#L170-L191>)仍未勾选，浅色及多窗口状态缺少当前截图 | 通过语法、令牌与挂载检查，不等于主题已经好看、已经定稿 |

**总体评价：方向值得继续，基础不薄；当前更缺少以真实画面为依据的精修闭环，而不是再增加一组效果。**

## 四、推荐的完整视觉方案

### 1. 构图：壁纸与界面共同设计

目标不是把壁纸变暗，而是让它在适合的位置有表现力。

- 保留人物、冷雾、冰柜和暖灯这些辨识元素，先不换图。
- 针对侧栏展开、侧栏收起、右侧面板打开、窄窗四种布局确定取景，不能只根据整窗宽高比裁图。
- 让高对比细节尽量落在正文版心之外；以主体偏移和阅读区柔和渐变一起解决，不靠全屏加黑。
- 阅读区边界应自然融入环境，避免中央突然出现一块矩形黑板。
- 空会话允许场景更完整；已有内容时仍保持同一套视觉身份，不让界面像突然换了皮肤。

验收问题：看一张有真实内容的整屏截图，能否同时认出主题、看清文字，并找到自然的第一视觉落点？

### 2. 材质：同源分工，不处处炫技

| 区域 | 推荐材质 | 期待观感 |
|---|---|---|
| 壁纸与边缘空间 | 清楚可辨的场景和局部冷暖光 | 有情绪，有景深，不像被一层灰糊住 |
| 侧栏、顶部导航 | 稳定的冷色磨砂，低反射 | 安静、有边界，不跟主内容抢亮度 |
| 正文区域 | 通透但稳定的阅读底 | 文字清晰，仍能感到场景存在 |
| 输入框 | 最精致的一块玻璃，局部亮棱与轻微折射 | 有触感，是主题的第二记忆点 |
| 菜单、弹窗、审批 | 同色系、较实的表面 | 精确、可靠，不把复杂背景透进操作文字 |
| 工具与交付卡 | 克制的冷色实体面，保留内容图标身份 | 与主题一致，又能迅速识别信息类型 |

实施重点：壁纸构图、阅读底、组件玻璃应分别控制。玻璃开关不应为了显效而全局抬高背景的存在感。

输入框的掠光应停留在材质层，不能覆盖文字、占位提示与图标后削弱对比。当前效果是否已造成此问题，需看实屏，不先判定。

### 3. 色彩：让蓝色更有节制，暖色更有价值

- 大面积使用低饱和蓝灰；冰蓝集中给选中、链接、主操作与焦点。
- 暖琥珀主要留在场景和局部光感中。可以保留现有用色限制，避免为了“有暖光”给每张卡片加黄边。
- 正文接近干净的冷白，辅助文字才逐级降低亮度；不能全部文字都染蓝。
- 成功、警告、失败保留语义独立性；警告用形状、图标与明确文字加以区分，不靠色相单独传意。
- 浅色版按“晨雾玻璃”独立调色：清透冷白、适量蓝灰、少量暖灯，不是把深色版整体增亮或反相。

保留现有主色作为起点，暂不为新版本增加一批未经实屏验证的十六进制颜色。

### 4. 布局与排版：舒展，但不能松散

- 保留中文正文与界面文字的两套尺度；现有正文 16px 附近、1.8 行距作为试验起点，不再盲目放大。
- 当前 44 字目标行宽先保留；窄窗优先适配容器，不能强行撑出固定宽度。
- 正文、输入框、内容卡片共享一条主对齐线。卡片不必全部同宽，网格关系必须清楚。
- 标题、段落、列表、引用和表格通过间距节奏形成层次，不只靠加粗和画边框。
- 先清理重复边框与过深嵌套，再考虑圆角微调；避免“卡片里套卡片”的后台感。
- 右侧面板打开后重新检查中心区域；长表格和代码块允许局部横向滚动，不牺牲整屏版心。

这里的尺寸都要由真实中文长文校准，不作为已经确认的最优值。

### 5. 组件：先打磨最常见的四块

**侧栏**

- 当前会话保留柔和底色和细标记，悬停不要与选中同强度。
- 分组标题、会话标题、时间与状态图标拉开层次。
- 状态、时间、操作入口的对齐节奏一致，长标题不挤坏右侧信息。

**输入框**

- 做成整套主题最精致、最明确的操作物。
- 发送、停止、附件、模型和权限入口有主次，不能一排同样亮。
- 空闲、输入中、正在生成、不可用四种状态属于同一设计家族；不能只给静止截图做装饰。
- 液态折射可作为局部增强；基础磨砂、描边和明暗层次本身就应好看，不以特定滤镜支持为前提。

**消息与过程**

- 正文是主角，工具运行和过程信息是次要信息；先检查当前布局，再决定是否需要新增折叠或密度能力。
- 不给每段话都套一块厚玻璃，不用各种彩色徽章制造热闹。
- 用户消息与助手正文有明确区别，又处在同一套空间和用色规则里。

**菜单、设置、交付卡**

- 菜单保持稳定底色、清楚选中态与键盘焦点。
- 交付物保留文件类型图标和内容差异，主要统一表面、边框与文字层级。
- 设置首页只展示少量高质量选择与真实预览。诊断信息移到可展开的高级区域；未证明必要时不新增一排透明度滑块。

### 6. 动效：增强触感，不制造视觉噪声

- 悬停、按下、展开和切换建议从 120–180ms 的轻过渡开始。
- 主要改变颜色、边框、阴影或局部透明度，尽量不改变内容位置。
- 不做持续流动的背景、循环扫光、呼吸边框和打字时的装饰动画。
- 尊重减少动态效果偏好；输入与滚动优先保持稳定。

## 五、明确不选的方向

| 方向 | 不推荐原因 |
|---|---|
| 为可读性把全屏压成黑灰 | 丢掉创作主题的初衷；优先尝试构图与局部阅读底解决 |
| 全界面液态玻璃、处处折射 | 局部效果容易互相争抢，信息层级反而消失 |
| 复制 Claude 或其他产品的外观 | 可以借鉴留白与层次，不能丢掉本主题独有的场景和冷暖关系 |
| 继续只调透明度、模糊与饱和度 | 缺少布局、组件、状态的一致设计，收益越来越低 |
| 为更多覆盖率而覆盖所有变量 | 覆盖量不是美观指标，不必要的覆盖增加维护风险 |
| 默认样式难读，靠专注模式补救 | 与用户的优先级冲突；专注模式只能是偏好，不是修复开关 |

## 六、实施顺序与停止条件

优先级按“对整屏美感的影响”排序，而不是按技术难度排序。

| 轮次 | 任务 | 可交付结果 | 进入下一轮的条件 |
|---|---|---|---|
| 1：定画面 | 留存当前基线；在真实 DSH 中精修深色默认模式的构图、阅读底与材质强弱 | 同内容、同窗口的前后对照；一套明确方向 | 用户认可整体画面，同时正文和主操作达到底线 |
| 2：定组件 | 打磨侧栏、输入框、消息过程和交付卡，统一对齐、边框与状态 | 核心组件在真实工作页中的效果与状态对照 | 高频区域无明显风格断层，运行时也不乱 |
| 3：定适配 | 独立精修浅色、窄窗、右侧面板展开、字号与缩放 | 多布局与明暗的真实页面证据 | 不是只在一张默认截图里好看 |
| 4：收口 | 交互、对比度、滚动和降级验证；同步设计文档与版本说明 | 可回滚的稳定版本与已知限制 | 美观由用户确认，技术证据与限制如实报告 |

每轮只解决一个视觉主问题，保留前后对照。不要同时改构图、字级、圆角、色板和所有卡片，导致无法判断究竟哪项改善了效果。

如果连续两次微调没有可见收益，先重审构图或材质分工，不继续机械叠加滤镜。

## 七、验收：两道门，不用平均分掩盖问题

### 第一门：美观，必须先获得明确认可

- [ ] 冷蓝与暖光仍有辨识度，壁纸不是被牺牲掉的背景。
- [ ] 整屏有稳定主次，人物、正文、输入框不争同一个落点。
- [ ] 玻璃有轻重差别，背景与前景有景深，没有灰糊感或过亮白边。
- [ ] 侧栏、输入框、内容卡、菜单与设置像同一套设计。
- [ ] 复杂内容下依然整齐，不是只在空会话中好看。
- [ ] 用户在同内容前后对照中更偏好新版；主观美感不包装成自动测试结论。

### 第二门：在既定美感里做到好用

- [ ] 默认氛围模式直接读长文、看表格、操作输入框，无须切专注模式。
- [ ] 当前会话、发送、停止、失败与完成能清楚识别；键盘焦点可见。
- [ ] 普通文字目标达到 4.5:1，大字目标 3:1；必要的控件边界与状态目标 3:1。
- [ ] 半透明界面按实际合成后的背景取样，在壁纸亮部、暗部与纹理位置复核；不只算前景色与一个假设底色。
- [ ] 侧栏与右侧面板开合、窄窗及 125%/150% 缩放不遮挡关键操作。
- [ ] 长回答、表格、代码、工具过程和附件同屏时仍保有清晰层级。
- [ ] 输入、长文滚动和切换不出现可感知的新增卡顿；用同内容前后对比，不凭代码猜性能。
- [ ] 关闭折射效果后仍是一套好看的主题，不退化成未设计的残缺界面。

至少覆盖六类真实页面：新会话、中文长文、表格/代码、工具执行与错误、交付物与右侧面板、设置与弹层。明暗主题都需复核；窄窗和缩放重点覆盖长文、输入框与弹层。

上述是目标清单，本轮没有宣称任何一项已经验收通过。

## 八、工程边界与下一步

- 优先复用现有主题令牌和已确认的设置扩展位；几何调整先验证宿主能力，不用不稳定选择器全面重写界面。
- 当前使用宿主构建专属类名的部分应单独维护和回归，不能把“选择器失配后回退”当作无需验收的保证。
- [窗口三键问题](<window-chrome-issue.md>)属于已有桌面端问题，本轮未复核或修复；另列跟进，不让它阻塞整屏视觉设计，也不以 CSS 假按钮遮盖。
- 不修改已打包安装文件，不直接搬入其他产品的全局样式，不改发送、权限和工具行为。
- 本轮只新增这份方案，未改主题代码和用户偏好。后续实施需由用户明确启动。

**获准实施后的第一步：获取当前默认模式的真实长文工作页截图和一张带输入框的截图，固定内容与窗口作为基线；首先调整构图和材质分工，不先增加特效。**
