# 玻璃肌肤 4.5 · 第 1 轮精修记录

日期：2026-10-18  
版本：4.4 → **4.5.0**  
范围：把「玻璃开关顺带改整片画布」这一处确认的耦合拆开，并补齐输入框的两级材质。  
不包含：浅色重构、窄窗/缩放验收、动效与组件几何的全面精修——那是后续轮次。

---

## 一、为什么先做这一件

上一轮评估里唯一被确认的结构问题：

> 玻璃开关还会改变整个画布的底色透明度。为了让输入框更透，正文背后的环境可能一起变化。

代码事实：`applyGlassTokens()` 在玻璃开启时把 `--dsw-alias-bg-base` 从 `0.12` 改写成 `0.02`
（浅色 `0.18 → 0.05`）。这个令牌由 `frame → centerCol → 会话根` 三个嵌套壳各画一遍，
alpha 按 `1 − (1 − a)³` 复合，所以一次改写影响的是整个窗口的阅读底，而不是输入框周围。

一个开关同时决定了两件事：**壁纸有多存在**、**输入框是什么材质**。前者是场景，后者是组件。
这一轮把它们拆成两个旋钮。

## 二、改了什么

| # | 变化 | 实现位置 | 用户可见结果 |
|---|---|---|---|
| 1 | **场景浓度独立** | `SCENE_BASE` + 令牌层 `dsh-glass-skin:scene`（只写 `--dsw-alias-bg-base`） | 设置页新增「清透 / 标准 / 沉静」三档；玻璃开关不再改画布 |
| 2 | **默认观感不变** | 默认 `clear` = 旧玻璃开启时的取值（深 0.02 / 浅 0.05） | 装上 4.5 打开就是旧样子；解耦没有顺带改默认风格 |
| 3 | **输入框材质分两级** | `html body [data-composer-card]`（基础）+ `body[data-dsh-glass-glass="on"]`（玻璃级） | 关掉折射仍是一张设计过的卡片：细边、顶部亮线、冷墨投影 |
| 4 | **掠光回到材质层** | 斜向掠光从 `::after + mix-blend-mode: screen` 移进卡片 `background` 多层渐变 | 光画在文字下面，不会洗到正在输入的那一行 |
| 5 | **侧栏磨砂变成结构** | `.BynINW_sidebarCol` / `.BynINW_frame:before` 去掉玻璃开关前缀 | 侧栏始终是安静的一层磨砂隔断，不随开关忽有忽无 |
| 6 | **跨端口持久化扩展** | `index.js` 的 `STATE_KEYS` + `mergeState` 增加 `scene`（白名单校验） | 三档选择和模式、玻璃一样，重启后还在 |
| 7 | **回归闸门扩展** | `skins/_tools/smoke-skin.mjs` + `verify.ps1` 增加 scene 属性与 scene 令牌层断言 | 场景层没接上会直接 FAIL，而不是静默退回 |

阅读纱（`body::after`）没有参与这次改动，这是有意的：**场景只决定壁纸露出多少，不决定正文好不好读**。
三档之间切换，正文的底不变。

## 四、没有验证的部分（不要当成已验收）

1. **没有目视定稿。** 本轮没有可用的图像通道：模型侧读不了图，宿主侧拿不到 Web 页令牌
   （`/` 返回 `dsh web authentication required`）。所以「更好看」这一条只能由你看。
2. **截图链路只证明了"截的是这个窗口"。** `tools/grab-window.ps1` 现在会先确认目标窗口在最前
   （`foreground=True` 才继续，否则 `exit 3`），但这只排除截错窗口，不代表图已被人看过并确认。
3. **合成后的对比度没有实测。** 半透明界面的真实对比度取决于宿主实际的 DOM 层叠
   （画布三层 + 阅读纱 + 工作层面板），没有页内取样就算不出来；离线按图层假设算出的数字
   会显得比实际更差或更好，等于伪精确。
4. **一个需要你目视核对的风险点。** 直接量了壁纸本身：正文列所在区域中位亮度 `0.55`、
   95 分位 `0.98`（右上象限偏亮）。场景=清透时画布几乎全透，正文的可读性完全由阅读纱承担。
   如果实屏上文字压在高亮区域仍显吃力，第一选择是加强阅读纱或换取景，而不是把整屏压暗。

## 五、怎么自己看

设置 →「玻璃肌肤」：

1. 场景浓度切「清透 / 标准 / 沉静」，看正文所在的底是否只改氛围、不改可读性。
2. 关掉「液态玻璃」，看输入框是否仍像一件设计过的器物（而不是退回宿主默认灰块）。
3. 再打开，看掠光是否只落在卡片边缘、没有盖住输入中的文字。

## 六、回滚

- **视觉回滚**：场景=清透 + 玻璃开启 = 4.4 的默认画布，无需改代码。
- **代码回滚点**：本次只动了三个文件——`client.js`（场景层、材质层、设置页）、
  `index.js`（`scene` 白名单）、`package.json`（版本与描述）；工具层动了
  `skins/_tools/smoke-skin.mjs`、`skins/_tools/verify.ps1`。4.4 源码没有单独存档，
  但改动集合就是上面第 2 节表格里的 7 项，逐项反向即可。
- 已装位置是符号链接（`~/.dsh/profiles/desktop/node_modules/dsh-glass-skin → D:\DeepSeek\skins\dsh-glass-skin`），
  所以本目录的改动就是已装版本；改完需要刷新页面（或重启桌面端）才生效。

## 七、下一轮建议（等你目视确认后再动）

1. 若「场景浓度」三档成立 → 进入第 2 轮：侧栏、输入框、消息过程、交付卡的对齐与四种状态
   （空闲 / 输入中 / 生成中 / 不可用）。
2. 浅色单独做「晨雾玻璃」：现在浅色只是同一套规则的取值，还没有自己的取景与材质判断。
3. 窄窗与 125%/150% 缩放：至少覆盖长文、输入框、弹层三类画面。
4. 动效收口：悬停/按下/展开 120–180ms，只动颜色与阴影，不做循环扫光。

**判定标准不变**：你看着觉得新版更好看，且默认模式直接可读可操作——两条都满足才算这一轮通过。
