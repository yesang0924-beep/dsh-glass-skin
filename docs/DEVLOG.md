# dsh-glass-skin · 玻璃肌肤

给 DeepSeek Harness Web UI 的壁纸主题：深夜便利店冰柜的冷雾与暖光。

灵感来自一张便利店的冰柜插画——前景是结霜的玻璃与冰蓝的冷雾，背景是便利店暖琥珀色的灯光。
落成主题后：**壁纸做底，冰蓝玻璃做层，暖光做高光**，文字始终压在暗色玻璃上。

## 5.3.1 智能体团队浮层并入操作面材质

「智能体团队」浮层（成员 / 共享任务）此前被当成弹窗：0.62 弹窗填充叠在宿主 0.78 菜单填充之下，等效 0.92，同一张背景还被模糊两次。现在它只走操作面配方——一份菜单填充、按面积取的 `blur(6px) saturate(155%)`、同一套 135° 冰霜掠光与亮边。

成员行与任务卡从 0.93 的硬片改为同一块玻璃上的 0.09 冰色微提亮（浅色 0.64 白），和设置弹窗里的卡片同一条规则。

标题栏「应用 / 编辑」下拉与输入框右键菜单是 Electron 主进程弹出的系统菜单，不在 DOM 里，CSS 改不到，仍由 Windows 自己绘制。若希望连这两处也统一，源码树里另有宿主补丁 `skins/_hostpatch`（把原生菜单换成页面内 HTML 菜单）；它不属于主题包，DSH 升级后需要重打。

**验证**：结构回归 **42/42**；六门禁 ALL PASSED；fixture v5.3.1（预览页已带团队浮层）。

## 5.3.0 稳定性与壁纸体验

材质与布局不变；这一版补的是「DSH 升级后能不能一眼发现钩子失配」和「换壁纸是否顺手」。

**宿主钩子自检**

设置 →「玻璃肌肤」→ 展开「设计说明与诊断」：窗口框架、侧栏、会话列表、输入框、设置弹窗是必需钩子；代码块、文档预览、交付卡是条件区域。`✓` 命中、`!` 未命中、`?` 设置页不可见未验证、`–` 当前页没有。汇总一行「必需 x/y 命中」，旁边「复制报告」把完整 JSON 诊断复制出来。DSH 升级后先看这里；开发树另有 `skins/_tools/verify.ps1` 的 coverage 门禁。

**壁纸亮度 / 对比提示**

选中壁纸时在本地对 32×20 采样，显示平均亮度与对比，并给一句场景建议（偏亮 → 标准/沉静；偏暗 → 清透/标准；适中 → 三种都可）。**只建议，不自动改场景**；换壁纸仍只写一个 CSS 变量。

**拖放 / 导入**

壁纸区支持拖入图片或点「导入图片」。Host 按 magic bytes 只收 JPEG/PNG/WebP，上限 32MB，文件名清洗为单段（中文保留，重名加 `-2`），原子写入后自动刷新并选中。上传路由是本地设置面板专用的单图入口，不是通用文件写入。

**验证**：结构回归 **41/41**；六门禁 ALL PASSED；fixture v5.3.0；新增上传路由测试（合法 PNG、路径穿越文件名、坏 magic、超限 content-length）。

## 5.2 封装：主题包自包含，壁纸移出安装包（5.3.0 沿用）

5.2 只做封装与稳定性，不改材质、排版和布局。

**装法**

- **开发**：本目录以 `link:` 装进 desktop profile；改 `client.js` 后 `Ctrl+R` 生效，改 `index.js` 需要重启 DSH。
- **分发**：`npm pack --pack-destination dist` 产出 `dsh-glass-skin-<版本>.tgz`。目标机解包后（`tar -xzf … -C <目录>`）用 `plugin_manager(install_bundle, target="<目录>/package")` 安装——`install_bundle` 对本地目录是 link 语义，不要直接指向 `.tgz`：那会留下“`file:` 说明符 + `link:` 锁定”的混合状态。包内自带宿主/客户端两半、内置壁纸、`LICENSE`、`CHANGELOG.md` 与 `tools/verify.mjs`，不依赖 `D:\DeepSeek` 的仓库目录。
- **自检**：`node tools/verify.mjs`（语法、版本一致性、42 条结构回归）。开发树另有 `skins/_tools/verify.ps1` 六道门禁（stylesheet / mount / coverage / fixture 等需要宿主源码的检查）。

**壁纸放在哪**

| 位置 | 用途 | 升级时 |
|---|---|---|
| `~/.dsh/dsh-glass-skin/wallpapers/` | 用户自己的图片，支持 jpg/jpeg/png/webp，文件名可用中文 | 保留 |
| 包内 `assets/wallpapers/` | 随主题发布的默认集 | 随包更新 |
| `~/.dsh/dsh-glass-skin.json` | 记住模式/场景/壁纸选择 | 保留；损坏时移到 `.corrupt-<时间戳>` |

同名文件用户目录优先。设置页有「刷新」按钮，把图片放进去后不用重启。

**换壁纸只换背景**

切换只重写 `--dsh-glass-wallpaper` 一个 CSS 变量；模式、场景、令牌、材质与布局都不参与。切换前等新图解码，失败或 8 秒超时会回退内置图并清掉失效指针；连续快速点两张时，先点的慢解码不会覆盖后点的选择。结构回归里有一条测试专门提取 `setWallpaper()` 的函数体，禁止它调用任何模式/场景/令牌函数。

## 5.0.0 冻结：换主题 = 换壁纸

设计到此冻结。材质、排版、状态、场景规则不再作为日常改动项；**壁纸是唯一可变参数**——它不参与任何材质计算，只决定画面。

两种换法：

1. **多套轮流用**：把图片放进 `~/.dsh/dsh-glass-skin/wallpapers/`（内置集在包内 `assets/wallpapers/`），设置页「壁纸」一栏会列出它们，点一下即切换。选择写进 `~/.dsh/dsh-glass-skin.json`，重启后仍在；换回内置图点「内置壁纸」。
2. **只换默认**：直接替换 `assets/wallpaper.jpg`，重载后生效。资源改为 `no-cache` + ETag，不再等一天缓存。

实现上的三条约束，也是"冻结"能成立的原因：

| 约束 | 做法 |
|---|---|
| 壁纸只有一个入口 | 唯一 CSS 变量 `--dsh-glass-wallpaper`；任何材质/排版/状态规则都不读它 |
| 切换不重建材质 | 只改写这个变量，等新图解码完成再切；失败回退内置图，不留空帧 |
| 样式表不在运行时重建 | 仍是同一个 `<style>` 节点原地改写（4.9.11 起） |

**验证状态**：`verify.ps1` 六道门禁全过（84 令牌）；结构回归 **41/41**，冻结闸门——整张样式表只能有一个图片 `url()`（就是内置壁纸默认值；5.1 的折射滤镜是 data-URI，单独计数）、壁纸切换必须经由单一 CSS 变量、Host 只列出用户目录与包内 `assets/wallpapers/` 里真实存在的图片且拒绝路径穿越（含真实调用 asset / wallpapers / state / upload 四条路由的测试）。

> **需要重启一次 DSH**：Host 侧路由与资源缓存策略只在应用启动时加载；`Ctrl+R` 只重读客户端。5.2 升级后同样需要重启一次，之后换壁纸只是点选或刷新。

## 4.9.11 稳定化：材质不再在运行时被重建

上一轮之后反馈"有的地方会闪烁，一会儿是清晰状态，一会儿又变成模糊状态"。这不是配色问题，是**材质被重建**：
输入框玻璃此前用 SVG `feDisplacementMap` 做边缘折射，配合 `ResizeObserver` 重写滤镜区域、再加一个
1.2 秒的重新挂载轮询。位移图异步解码、换行改区域、节点重建，都会让 Chromium 先画一帧未处理的背景——
看起来就是卡片在清晰与磨砂之间闪。

| 触发点 | 4.9.10 | 4.9.11 |
|---|---|---|
| 输入框玻璃 | `backdrop-filter: url(#dsh-glass-liquid) blur(10px)…` | 纯 CSS `blur(10px) saturate(180%)…`，运行时不可变 |
| 挂载方式 | 1.2s 轮询 + ResizeObserver + SVG 节点 | 无脚本；样式表直接生效 |
| 禁用态 | `backdrop-filter: none` | 保留模糊，只改填充（96% 已遮住背景） |
| 发送键 / `+` | `transition` 含 background（渐变不可插值，会分成两种材质） | 只过渡 `box-shadow` / `color` |
| 样式表重挂载 | 先删后加，会有一帧没有皮肤 | 同一个 `<style>` 节点原地改写 |

**验证状态**：`verify.ps1` 六道门禁全过（84 令牌）；结构回归 22/22，新增三道稳定性闸门——
`backdrop-filter` 不得出现 `url()`、SVG 位移与定时挂载必须不存在、禁用态不得删除模糊、
控件的 transition 不得含 background。视觉仍需实屏确认：卡片应始终是同一块磨砂，不再闪；
边缘折射换成掠光后强度更柔和。

## 4.9.10 发送键改成玻璃：和 + 共用同一套配方

上一版把发送键从宿主亮蓝换成了主题冰蓝，但那仍是一块**实心圆片**。用户纠正："我的意思是要材质……材质是玻璃材质的那种……我们其他所有 UI 的材质都是玻璃材质。"

所以这版不再给发送键单独写配方，直接把它并入 composer 上 `+` 控件的同一条规则：

| 项 | 4.9.9 | 4.9.10 |
|---|---|---|
| 发送键底 | 实心冰蓝 `button-info-fill` | 与 `+` 同一条玻璃：`input-major` 半透明 + 135° 白→冰霜掠光 + `inset 0 1px 0` 亮顶边 + 0.5px 边 |
| 玻璃档 | 只有 `+` 跟随 46% | `+` 与发送键一起 46%，hover 一起 62% |
| 箭头 | 主色前景墨（实心底） | `label-primary`，与 `+` 图标同色 |
| disabled | 宿主 `opacity:.4` | 与 `+` 同一套 disabled 配方（`opacity:1`，玻璃自己变淡） |

发送键和 `+` 现在是同一材质的两个尺寸；照片仍从按钮底下透出来。4.9.9 的 info 令牌映射保留——不是发送键的底，而是其他 info 控件的颜色兜底。

**验证状态**：`verify.ps1` 六道门禁全过（84 令牌）；结构回归 19/19（发送键必须出现在 `+` 的同一条玻璃规则里、不得再有单独的实心规则）；`window-chrome-color.ps1 -Check` 6/6。改前图 `docs/shots/4.9.9-send-button-before.png`；改后实屏待补（窗口最小化/高权限）。

## 4.9.9 发送键归入 primary 阶梯

> **4.9.10 更正**：这一版只统一了颜色，发送键仍是一块实心圆片；用户要的是玻璃材质。4.9.10 把它并入 `+` 的玻璃规则，下面的 info 映射保留为颜色兜底。

现场反馈（截图：composer 右下角的蓝色圆形发送键）："把这个漏掉了，也给它的材质改成我们统一的UI材质。"

这是主题里最后一处"别的蓝"。宿主用 `.RlGAzG_primary` 画发送/停止键：填充是 `--dsw-alias-button-info-fill`（解析到 `--dsw-static-deepseek-400`，亮蓝 `#7aaaff`），符号色硬编码为 `#fff`。皮肤的令牌层只映射了 `button-primary-fill/hover`，没有映射 `button-info-*`，所以这颗按钮一直保持着它的亮蓝圆片外观。

改法是把 info 并进 primary 阶梯，而不是单独给这颗按钮调色：

| 项 | 4.9.8 | 4.9.9 |
|---|---|---|
| `--dsw-alias-button-info-fill` | 宿主 `deepseek-400`（`#7aaaff`） | 深色 `#8fd1ee` / 浅色 `#24708f`（与 primary 同值） |
| `--dsw-alias-button-info-hover` | 宿主 `deepseek-500` | 深色 `#a8ddf3` / 浅色 `#1f607b`（与 primary 同值） |
| 符号色 | 宿主硬编码 `#fff` | `--dsw-alias-label-primary-foreground`（深色 `#06202c` / 浅色 `#f6fcff`） |
| 材质 | 纯色圆片 | 加 `inset 0 1px 0` 亮顶边 + `0.5px` 主色边，与 composer 上其它控件同族 |

箭头用 `currentColor`，会和符号色一起翻：深色主题是冰蓝底 + 深墨箭头（对比度约 10:1），浅色主题是深青底 + 近白箭头（约 5.4:1，仍过 AA）。hover 只换填充，不额外加发光。

**验证状态**：`verify.ps1` 六道门禁全过（84 令牌）；结构回归 19/19（新增"发送键使用 primary 阶梯、info 令牌与 primary 同值、不得出现 #7aaaff"）；`window-chrome-color.ps1 -Check` 6/6。改前现场图存 `docs/shots/4.9.9-send-button-before.png`（90×84 的按钮裁切）。改后实屏图待补：运行窗口仍是最小化/高权限，需重载后人工确认。

## 4.9.8 会话列表底部渐隐：它不是阴影，是第二层墨

现场反馈（截图：会话列表最末一行出现一块深色带，像阴影）："这边为什么有个阴影啊？其他地方都没有，只有这里有。"

先排除了行的状态。拿到的 DOM 里这一行是：

`<div class="hIlkoa_sessionRow" role="treeitem" aria-selected="false" draggable="true">…`

没有 `hIlkoa_selected`、没有 `hIlkoa_menuOpen`、`aria-selected` 为 false；会话行 CSS 里也没有任何 `box-shadow`。所以它不是选中、悬停或拖动预览中的任何一种。

真正画出这块的是宿主会话列表的底部渐隐：

```css
._9lTDKa_fade {
  position: absolute; bottom: 0; height: 24px; pointer-events: none;
  left: 0; right: var(--dsh-session-list-edge-inset);
  background: linear-gradient(to bottom, transparent, var(--dsw-specific-sidebar-fill));
}
```

在默认的不透明侧栏里，`--dsw-specific-sidebar-fill` 就是侧栏自己的表面，"渐隐到它"等于看不见。玻璃肌肤把这个令牌重新定义成压在照片上的**墨色**（深色 0.44），于是这层渐隐变成**第二层墨**：列表视图底部固定 24px 的深色渐变，正好盖住最末一行，读起来就是一道阴影。它钉在列表底部，不跟着哪一行走，也不受鼠标影响——与现场"一直都有、只有这里有"完全吻合。

改法：删掉这层渐隐（`display: none`），不是给它换颜色。列表末端已经接到 footer，渐隐没有要遮的东西；留下只会是这个主题里最后一层多余的墨。

| 项 | 4.9.7 | 4.9.8 |
|---|---|---|
| 列表底部 | 宿主渐隐到 sidebar-fill（透明面上 = 第二层墨） | `display: none` |
| 最末一行 | 被 24px 深色渐变盖住，像一道阴影 | 与其它行同一张面，footer 边缘是干净的硬边 |

**验证状态**：`verify.ps1` 六道门禁全过（82 令牌）；结构回归 18/18（新增"列表底部渐隐不得再画"）；`window-chrome-color.ps1 -Check` 6/6。改前现场图存 `docs/shots/4.9.8-fade-before.png`（4× 放大 `4.9.8-fade-before-zoom.png`）。改后实屏图待补：这一轮拿到了用户的 DOM 片段，能确认真凶是 `_9lTDKa_fade`；运行窗口仍是高权限/最小化状态，重载后的实屏截图仍需人工确认。

## 4.9.7 顶栏并面：整窗一块材质

现场反馈（截图：标题栏与下方工作区上下两条带）："其实我们可以让这两个材质一样……这样就真正的浑然一体了。"

4.9.0 把侧栏并进了正文，顶栏却还留着最后一层自己的配方：0.32 墨色 + `blur(14px)` 采样 + 冷/暖双色 wash + 顶部亮线。下面的正文是"清晰壁纸 + bg-base + sidebar-fill"，上面是"模糊壁纸 + 另一套墨色"——同一张壁纸在 40px 处从模糊切成清晰、从一套合成切成另一套，读起来就是压在工作区上的一条独立横带。

改法只有一句：**顶栏的 `::before` 改画正文那条合成**——`linear-gradient(bg-base, bg-base)` 叠 `sidebar-fill`，`backdrop-filter: none`，无 wash、无亮线、无内阴影。几何与拖拽区不动，原生三键仍交全透明（4.9.5）。

顺带删掉整层壳层变量：`--dsh-glass-shell-fill/edge/cool/warm/top/blur/rim` 在新配方里没有任何消费者，留着只会再长出第二套配方。`prefers-reduced-transparency` 分支也随之删除——它原本只改壳层；现在页面透明度只由场景令牌（`--dsw-alias-bg-base`）决定，专注模式走自己的令牌覆盖，无磨砂降级只留着气泡与代码块。

| 项 | 4.9.6 | 4.9.7 |
|---|---|---|
| 顶栏底 | 0.32 墨 + `blur(14px)` + 冷暖 wash + 顶部亮线 | 正文同款：bg-base 叠 sidebar-fill，无采样 |
| 顶栏与正文接缝 | 模糊→清晰、两套合成，一条可见步进 | 同一张清晰壁纸、同一套合成，没有可画接缝的差异 |
| 壳层变量 | 7 个 | 0 个 |
| 窗口三键 | 交给系统透明，落在顶栏上 | 不变（现在落在与正文同一张面上） |

**改前实测**（用户现场截图，已存 `docs/shots/4.9.7-user-before.png`，1923×153 的顶带裁切）：同一 x 上把顶带（y 18–42）与紧邻正文（y 66–90）各取 40px 宽均值，6 个取样点（x=300…1800）的步进为 R 9–29 / G 3–27 / B 4–34，顶带一致偏亮。那是两套合成之差，不是壁纸自身的竖向变化。

**验证状态**：`verify.ps1` 六道门禁全过（82 令牌）；结构回归 17/17（新增"顶栏 = 正文材质、无 blur、壳层变量不得复活"）；`window-chrome-color.ps1 -Check` 六项通过（三键仍交全透明）。**改后实屏待补**：桌面窗口当前最小化且以更高完整性级别运行（低权限进程恢复/截图/读令牌均被拒：`ShowWindow` 无效、`PrintWindow` 返回空白、`OpenProcessToken` → `ERROR_ACCESS_DENIED`），取不到前台截图；改后顶栏与正文由同一条声明绘制，接缝应只剩壁纸自身的缓慢变化，需重载后实屏复核，并用 `tools/measure-regions.ps1` 复测同一组取样点。

## 4.9.6 去掉「液态玻璃」开关

现场反馈："这个东西其实可以搞掉了，因为我们默认它是开着的……我们根本没必要把什么好的东西再搞开关啥的，它直接就开着就行了。"

「液态玻璃 · 输入框材质」原本是设置页里的一个开关：开着时输入框使用位移贴图 + 薄模糊 + 掠光的液态玻璃，关掉退回普通玻璃。创建者从未关过它。

这已经是**第二次**删掉"通往最佳状态的开关"（4.9.4 删了「跟随系统」）。所以它不再当个案处理，作为规则写进 DESIGN：**主题只交付最佳状态，不交付通往它的开关**。

| 处 | 改法 |
|---|---|
| 设置页 | 整行删除（标题、说明、开关一起） |
| `client.js` | `glassOn = true` 常量；删 `readGlass` / `setGlass` / `emitGlass` / `subscribeGlass` 与 `glassListeners`；`paintGlass()` 恒写 `data-dsh-glass-glass="on"` |
| 宿主值采纳 | **删掉 glass 分支**——旧状态文件里若有 `"glass": false`，采纳它就是绕过界面把材质关掉 |
| 样式 | `.dsh-glass-glass*` 那四条设置页行样式一并删除；`body[data-dsh-glass-glass="on"]` 的材质规则**照旧保留**（属性现在恒为 on） |

**验证状态**：`verify.ps1` 六道门禁全过（82 令牌）；`readGlass|setGlass|emitGlass|subscribeGlass|GLASS_KEY|glassListeners` 引用已全部清零。

## 4.9.5 代码块模糊半径按面积取 6px

现场反馈："这个代码块有点格格不入了，它这个材质。"

4.9.2 把代码块的 `backdrop-filter` 从 `blur(10px)` 统一成 `blur(14px)`，理由是"和气泡同一套配方"。这次实测发现那个统一推错了方向——**在 14px 下，壁纸的一切结构都被抹平，大面积面板就变成一块均匀的深灰蓝矩形**，贴在明亮的照片上当然格格不入。气泡只有 30px 高，糊掉无所谓；代码块是几百像素宽的面，糊掉就等于放弃了"这是玻璃"的唯一证据。

同一张壁纸、同一段代码，四种参数并排（`docs/shots/4.9.5-codeblock-materials.png`）：0.66/blur14（原状）、0.56/blur14、0.66/blur6、0.56/blur6。结论很直接：**变透明度只是让它变亮，变模糊半径才让它重新变成玻璃**。0.66 + blur6 这一档下，角色的脸、货架横条、外套轮廓都能透出来，而文字对比度仍是 8.59:1。

| 项 | 4.9.2 | 4.9.5 |
|---|---|---|
| 代码块 `backdrop-filter` | `blur(14px) saturate(155%)` | `blur(6px) saturate(155%)` |
| banner（同属这块面） | `blur(12px)` | `blur(6px)`，与本体一致 |
| 底板透明度 | 0.66 | 0.66（不动，可读性优先） |

**修正一条 4.9.2 的结论**：当时说"前三块内容面共用一套模糊配方"，是把"饱和度和亮边要统一"错误地推广到了"半径也要统一"。修正后的规则是——**`saturate` 统一，`blur` 半径按面积分配**：面积越大越不该糊，否则结构消失、面板塌成色块。

**验证状态**：`verify.ps1` 六道门禁全过（82 令牌）。材质对比图由 `_tools/codeblock-materials.py` 在真实壁纸上合成（PIL，因为本机 CDP Chrome 不绘制位图），并同时输出合成色与两个对比度数值。

## 4.9.4 去掉「跟随系统」

创建者一句话："感觉我们没必要搞一个跟随系统的选项吧。"

「窗口玻璃」原本是 **通透玻璃 / 跟随系统** 两选一。`跟随系统` 的意思是：当 Windows 打开「减少透明效果」时，顶栏与侧栏退成接近实色的衬底。但这套主题的前提就是"壁纸做底、冰蓝玻璃做层"，一个让玻璃退成实色的选项，与主题本身相抵；而创建者从来只用通透。

所以删掉，不是隐藏：

| 处 | 改法 |
|---|---|
| 设置页 | 「窗口玻璃」只剩一个「通透玻璃」，说明文字改成单一句，不再提分叉 |
| `client.js` | `TRANSPARENCIES = ['glass']`；`readTransparency` 用 `includes` 判断，读到旧值 `system` 自动折回 `glass` |
| `index.js` | 宿主侧只接受 `transparency: 'glass'`，旧客户端的 `system` 补丁不再写进状态文件 |
| `smoke-skin.mjs` | 状态 stub 仍然serve 旧值 `system`，断言输出必须是 `glass` —— 删掉的选项不能借旧存档复活 |

CSS 里那组 `body:not([data-dsh-glass-transparency="glass"])` 的降级规则**保留不动**：属性现在恒为 `glass`，规则永不命中，属于兜底；删掉它反而会在首帧属性尚未写入时暴露出来。

**验证状态**：`verify.ps1` 六道门禁全过（82 令牌）。这一版提交时 `fixture` 门禁立刻报了 `out of date: skin.css, version.txt` —— 版本号进了 CSS，夹具必须跟着重生成，正好验证了 4.9.3 建的那道闸门在工作。冒烟测试输出 `window transparency attribute: body=glass`。

## 4.9.3 验证链路：夹具从 client.js 生成

这不是视觉改动，是**防止再拿过期截图做判断**。

问题：预览夹具里的令牌是一份**手工摘出来的静态副本**（`before.css` 里 0.76、0.82 那些值）。`client.js` 改成 0.66 之后，夹具仍显示 0.76——4.9.1 和 4.9.2 两轮的改动它一次都没跟上。谁打开那个预览，看到的是两版之前的皮肤。

改法：

| 项 | 之前 | 现在 |
|---|---|---|
| 夹具令牌 | 手抄一份，随 client.js 漂移 | `_tools/build-fixture.mjs` 从 `AMBIENT_TOKENS` / `FOCUS_OVERRIDES` / `SCENE_BASE` 直接提取生成 `tokens-dark.css` / `tokens-light.css` |
| 夹具样式 | 手抄 `skin.css` 快照 | 从 `client.js` 的 CSS 模板提取，解析 `${VERSION}` / `${WALLPAPER}` 两个插值 |
| 夹具页面 | `.tmp` 下的临时文件 | `skins/_fixture/dark.html` / `light.html`，自包含 |
| 门禁 | 五道（语法、样式表、宿主语法、挂载、覆盖率） | **六道**，新增 `fixture`：夹具与 `client.js` 不一致就失败，并提示重跑生成器 |
| 版本 | `package.json` 与 `client.js` 各写一份，会漂 | 新增断言：两处不一致直接失败（4.9.2 就出现过 `client.js` 还写 4.9.0） |

**两条已知限制（实测，不是推测）**：

1. **这个环境的 CDP Chrome 不绘制位图**。壁纸能加载（`new Image()` 解码出 2048×1143），但 `background-image` 和 `<img>` 都不出现在截图里。所以夹具截图**没有壁纸**，它验证的是令牌值、规则落点、透明度与语法色，不是最终观感。要看照片请直接用普通浏览器打开 `skins/_fixture/dark.html`。
2. 夹具的 DOM 骨架是手写的（只有宿主能渲染真实界面），`base.css` 手工提供宿主不归皮肤管的几何量与默认令牌（圆角、elevation、字体）。缺了它们，皮肤的 `var()` 链会整条失效——这是它第一次跑起来时踩到的坑。

## 4.9.2 代码块：一块面，不是一块面加一个盖

现场反馈："类似这样的 UI，把它的颜色、质量、透明度统一就好了，统一才是最好看的。"

查下来代码块是整套材质里唯一**自己和自己分层**的地方：底板 0.76，banner 又用 0.82 以 82% 叠在上面——等效约 **0.96**，几乎是实心的。所以它看起来像"一张卡上又盖了一块板"，和页面其他一层层透出壁纸的表面不在同一套语言里。

| 项 | 4.9.1 | 4.9.2 |
|---|---|---|
| 底板 | 深 `rgba(19,32,47,.76)` / 浅 `rgba(238,246,252,.88)` | 深 `rgba(21,34,49,.66)` / 浅 `rgba(240,247,252,.80)` |
| banner | 独立 0.82，等效叠成 0.96 | **与底板同值**，改用 `backdrop-filter: blur(12px)` 遮滚动内容 |
| 模糊 | `blur(10px) saturate(150%)` | `blur(14px) saturate(155%)`，与气泡同一配方 |
| 顶纱 | `rgba(255,255,255,10%)` | `color-mix(label-primary 7%)`，与输入框同一条配方 |
| 投影 | 自定义 `0 2px 12px` | `--dsw-elevation-soft` |
| 任务卡 | `saturate(150%)` + `#ffffff 14%` 顶纱 | `saturate(155%)` + `label-primary 7%` 顶纱（16px 半径保留） |
| 专注模式 | 0.90 | 0.86（保持比 ambient 实一档） |

**阶梯**：气泡 0.58（读）→ 代码块 0.66（读很久）→ 菜单 0.78（操作）→ 输入框 0.88（主操作面）。

**统一的是配方，不是数值**：每块表面的透明度仍按"被读多久、要不要挡住背景"分开；统一的是同一套模糊、同一条亮边、同一个阴影层级，以及"一个表面只有一个透明度，绝不自己叠自己"——banner 的 0.82 本质上是在补偿它需要一个更实的底来遮滚动文字，改用背景模糊之后这层补偿就不需要了。

**验证状态**：`verify.ps1` 五道门禁全过（82 令牌）。这一版是纯令牌与规则数值改动，未新增选择器；观感需 `Ctrl+R` 后实屏确认。

### 侧栏与正文并面（4.9）

**现场反馈**：左栏仍像一块单独的面板，和正文之间有一条竖线；希望两边用同一种透明度，"不让它们中间分隔开来"。

| 层 | 4.8 的做法 | 4.9 的做法 |
|---|---|---|
| 侧栏底 | 自己的磨砂层：`--dsh-glass-shell-*` 三段渐变 + `blur(14px)` + 右侧 0.5px rim | 直接复用正文的合成：`--dsw-alias-bg-base` 叠 `--dsw-specific-sidebar-fill`，`backdrop-filter: none`、无渐变、无内阴影 |
| 分隔线 | 宿主 `.BynINW_sidebarCol` 的 `border-right: .5px` + 皮肤的内侧 rim | `border-right: none`，两条都去掉 |
| 正文圆角 | 宿主给 `.BynINW_centerCol` 的 `border-top-left-radius: 16px`，会在接缝处切出一个圆角缺口 | `border-top-left-radius: 0`，两栏拼成一块面 |
| 顶栏 | 与侧栏共用同一套磨砂 | 4.9 时仍保留磨砂；**4.9.7 起也并面**，与正文画同一套合成、不再采样（见上） |

这样侧栏与正文在**同一张壁纸、同一层阅读纱、同一层工作色调**上合成，壁纸的清晰度也一致（不再一边模糊一边清晰）。代价是侧栏不再有独立的冷雾渐变与磨砂——这正是"并面"要的：整窗只有一块工作区；4.9.7 又把最后那条顶栏横带也并了进去。

**一个不在主题能力范围内的卡顿源**：文件预览的「自动刷新」出厂默认开启（`autoRefresh: true`）。当 Agent 写入当前预览的文件（例如 114 KB 的 `client.js`）时，预览会整份重读并重新高亮，2,700 行代码在主线程上反复重建，页面会停住——主题改不了宿主的默认值。边看代码边让 Agent 改文件时，点预览头部的暂停键关掉自动刷新，或先关面板再让它改。

## 4.8.0 统一视觉：同一张背景上的分级玻璃

目标不再是"把深色卡片调浅一点"，而是让每块表面都属于同一背景，只是**重量不同**：气泡最轻、代码块最稳、任务卡是控件、菜单与弹窗必须挡住背后。改动全部落在令牌与可访问性钩子上，未碰布局骨架、业务功能、场景浓度和输入框四态配方。

| 区域 | 改了什么 | 量化的依据 |
|---|---|---|

## 它做了什么

| 层 | 实现 |
|---|---|
| 场景 | `body::before` 固定层：壁纸 + 两团取自画面本身的色晕 + 压暗纱，按窗口比例换焦点；`filter: blur + saturate` 做磨砂 |
| 阅读纱 | `body::after` 独立一层，与壁纸分开——专注模式压暗壁纸时，文字底下的纱不变弱 |
| 配色 | `ctx.theme.overrideTokens()` 提交 60 个 token（浅色/深色各一套），由宿主 `ThemePresenter` 投到 `body` |
| 排版 | 本插件样式表以 `html body` 覆盖宿主在 `body` 上声明的 `--dsw-font-markdown-*`，靠特异性取胜，不靠加载顺序 |
| 材质 | 冷墨投影 `--dsw-shadow-lv1/2/3`、滚动条冷色、选区冷色 |

不替换任何业务组件、不 shadow 宿主 UI、不引入第三方运行时依赖。
